# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

The renderer is HTML and CSS inside an Electron desktop app for macOS, Windows, and Linux. It is not served as a website. The marketing site in `site/` is a separate static page.

## Users

Developers who use Claude Code or Codex and are moving to another computer, such as a new laptop, or between two computers they own. They want their local agent sessions to come along so `claude --resume` or `codex resume` continues the conversation on the new machine.

## Product Purpose

Agent Session Mover lists the Claude Code and Codex sessions stored on this computer, exports the ones the user picks into one `.agentsessions` file, and imports that file on another computer. Success is that every imported session resumes on the new computer from the right project folder, with its full history and subagents.

## Positioning

Coding agents keep each session on the machine where it ran, and neither CLI has a way to move one. This app reads what each CLI writes to disk, rewrites project paths for the new computer, and puts the files where the agent looks for them. Cloud sessions already follow the account, so it moves only local ones.

## Operating Context

- Used occasionally, around a machine change. It runs export on one computer and import on the other.
- The user moves the archive themselves, by AirDrop, USB, cloud drive, or similar.
- Code is not part of the archive. The user pushes and pulls with git, or copies the folder, before resuming.
- After import, the user runs the resume command the app shows, in a terminal.

## Capabilities and Constraints

- Browse sessions by project folder, search titles, folders, and session ids, and preview a conversation before export.
- Export selected sessions, with their subagents, into one `.agentsessions` archive.
- Import asks where each project lives on the new computer, and can create a missing folder.
- Nothing is written until the user starts the import. A failed import rolls back. Replacing an existing session keeps a backup of the old copy.
- Supports Claude Code (`~/.claude/projects` or `CLAUDE_CONFIG_DIR`) and Codex (`~/.codex/sessions` or `CODEX_HOME`) only.
- The app cannot start the agent to confirm a session opens. It checks only that the files are in place.
- Terminology: session, project folder, archive (`.agentsessions`), mapping, resume command, backup.
- Stable identifiers that must not change: bundle ID `com.karlhsueh.agent-sessions`, data folder `agent-sessions`, archive format and extension, localStorage keys `agent-sessions.*`.

## Brand Commitments

- Name: Agent Session Mover. Chosen to say what it does, and to avoid a clash with another Mac app called Agent Sessions.
- App icon at `build/icon.png`.
- Voice: plain, literal, specific. Says what the app does and what it will not do, without marketing claims.
- Local only. No account, no cloud service, no telemetry. The only network request is the update check on GitHub.

## Product Principles

1. Feel like a native desktop app, not a web page: standard menus, keyboard shortcuts, and title bar behavior.
2. Show what is at risk before anything happens. Say plainly what an archive contains and what an import will overwrite, before any write.
3. Stay local. No feature may add an account, a cloud dependency, or telemetry.
4. Same on every platform. Windows and Linux get the same layout and features as macOS.

## Accessibility & Inclusion

No formal standard. Keep the basics: full keyboard use, readable contrast, and screen reader labels.
